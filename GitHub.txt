# 1. O que você já tem

Hoje a arquitetura é aproximadamente:

```text
                    ┌─────────────────┐
                    │   Roteirista    │
                    │      LLM        │
                    └────────┬────────┘
                             │
                       cria cenário
                             │
              ┌──────────────┴──────────────┐
              │                             │
          personagem                    personagem
              │                             │
           SQLite                        SQLite
              │                             │
        personalidade                 personalidade
        memória                       memória
        emoções                       emoções
        relações                      relações
              │                             │
              └──────────┬──────────────────┘
                         │
                    llama-server
                         │
                       LLM 7B
```

O ponto que mais gostei é esta decisão arquitetural:

> **o LLM não decide diretamente o estado do personagem.**

`decidir()` determina `REVELAR`, `ESCONDER` ou `MENTIR`, enquanto o LLM recebe uma instrução já determinada e apenas transforma isso em fala. 

Isso é excelente para um sistema local porque você não precisa gastar tokens tentando fazer o modelo "pensar" em tudo.

# 4. A diferença entre "verdade" e "crença"

Essa seria uma das maiores melhorias.

Hoje existe essencialmente:

```text
memoria = fato que o personagem sabe
```

Eu adicionaria:

```text
WORLD FACT
     │
     ├── verdade objetiva
     │
     ├── observação
     │
     └── interpretação
```

Por exemplo:

### Mundo

```text
João pegou a faca às 21:30.
```

### Maria viu

```text
Maria:
"Vi João perto da cozinha."
```

### Maria acredita

```text
Maria:
"João provavelmente pegou a faca."
```

### João sabe

```text
João:
"Eu peguei a faca."
```

### Carlos acredita

```text
Carlos:
"Maria está mentindo."
```

Isso cria uma coisa muito poderosa:

## crenças incorretas.

E aí os agentes realmente começam a parecer diferentes.

# 5. Sistema de crenças

Eu adicionaria à tabela:

```sql
CREATE TABLE crencas (
    id INTEGER PRIMARY KEY,
    assunto TEXT,
    proposicao TEXT,
    confianca REAL,
    origem TEXT,
    evidencias TEXT,
    atualizado_em REAL
);
```

Por exemplo:

```text
Carlos acredita:

"João roubou o dinheiro"
confiança: 0.73

origem:
Maria

evidências:
- Maria disse que viu João
- João estava perto do cofre
```

Mas pode estar errado.

Isso permite:

```text
verdade ≠ crença
```

E isso é ouro para o seu projeto.

# 8. Memória semântica

Hoje sua busca é baseada em palavras compartilhadas e até corta palavras em 5 caracteres. É barata, mas limitada. O próprio projeto já aponta FTS5/embeddings como próximo passo. 

Eu faria:

```text
                    memória
                       │
             ┌─────────┴─────────┐
             │                   │
          FTS5                 vetor
             │                   │
       busca exata         busca semântica
             │                   │
             └─────────┬─────────┘
                       ▼
                 reranking
                       ▼
                  top K fatos
```

E nem precisa usar um LLM para isso.

Pode usar:

* SQLite FTS5
* `sqlite-vec`
* `fastembed`
* embeddings pequenos

Isso permite:

```text

"Quem estava perto do cofre?"

Memória:
"Eu vi Carlos saindo da sala onde ficava o cofre."

→ relevante
```

mesmo sem compartilhar exatamente as mesmas palavras.

```text

```

ter:

```text

   ↓
avaliar situação
   ↓
objetivos
   ↓
ações possíveis
   ↓
selecionar ação
   ↓
executar
   ↓
mudar mundo
```

Exemplo:

```text
João percebe:

Carlos está desconfiado.

ações:

[1] mentir
[2] ameaçar
[3] fugir
[4] incriminar Maria
[5] ficar calado
[6] mudar assunto
```

O seu `decidir()` atual poderia evoluir para algo muito mais geral:

```python
acao = agente.escolher_acao(
    situacao,
    objetivos,
    crencas,
    personalidade,
    relacoes
)
```

# 19. Um "motor de fofoca"

Isso combina **perfeitamente** com o projeto.

Imagine:

```text
Maria → Carlos:

"João estava perto do cofre."
```

Carlos registra:

```text
origem = Maria
confiabilidade = 0.73
```

Depois:

```text
Carlos → Ana:

"Maria disse que João estava perto do cofre."
```

Ana registra:

```text
origem = Carlos
origem_original = Maria
```

E depois:

```text
Ana → João:

"Estão dizendo que você roubou o dinheiro."
```

Agora você tem **propagação de informação**.

E pode adicionar distorção:

```text
Maria:
"João estava perto do cofre."

↓

Carlos:
"Maria acha que João mexeu no cofre."

↓

Ana:
"Maria disse que João roubou."

↓

João:
"Estão dizendo que Maria me acusou de roubo."
```

Isso seria MUITO legal no Contracenador.

| 🟡 11      | Interface gráfica             | Médio      |
| 🟡 12      | Voz/avatar                    | Depois     |

**Eu não começaria pela interface gráfica nem por modelos maiores.** A parte mais valiosa do seu projeto é justamente o **motor de simulação** que já está aparecendo por baixo do código.

E tem uma oportunidade particularmente boa aqui: **transformar o Contracenador em uma engine genérica de agentes, deixando "investigação criminal" como apenas um tipo de cenário/plugin**. O seu `roteirista.py` já está caminhando nessa direção ao separar geração do cenário da materialização dos agentes. 

Se você quiser continuar esse projeto seriamente, o próximo passo que eu faria é **desenhar a arquitetura 2.0 completa antes de alterar o código**: banco de dados do mundo + banco dos agentes + sistema de eventos + crenças + evidências + objetivos + ações + scheduler + LLM. Isso evitaria você precisar reescrever `Ator.py` inteiro depois.
